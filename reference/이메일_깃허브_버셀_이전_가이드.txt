이메일 변경 시 깃허브/버셀 계정 이전 가이드 (작성 2026-08-25)

[상황]
- 현재 구글 이메일로 깃허브 가입 → 그 깃허브로 버셀 가입한 상태
- 새 이메일을 만들어서 깃허브/버셀도 새로 가입하고, 현재 프로젝트를 새 깃허브로 옮기려는 계획

[결론]
- 기존 계정의 이메일만 바꾸는 것보다, 새 이메일로 깃허브/버셀을 아예 새로 가입하는 쪽이 더 안전하고 단순함
- 현재 프로젝트는 서버 함수/환경변수/API 키가 전혀 없는 순수 프론트엔드+LocalStorage 구조라 이전 자체는 어렵지 않음

[잘 되는 부분]
- 로컬 저장소(C:\PJY_Vibe_Web\tuk-tak)를 새 깃허브 저장소에 push하면 커밋 히스토리 전부 보존됨. 코드 손실 없음
- 옮길 API 키/시크릿이 없어서 버셀 재연결도 단순함

[진짜 중요한 리스크 — PWA 데이터]
- 지금 배포 URL(tuk-tak-beta.vercel.app)로 폰에 PWA를 설치해서 문장 데이터를 쌓아둔 상태
- LocalStorage는 도메인(origin) 단위로 저장되므로, 새 버셀 계정에서 재배포하면 URL이 달라질 가능성이 높음
  (기존 tuk-tak-beta 서브도메인은 옛 버셀 계정이 이미 점유 중이라 새 계정에서 똑같이 못 가져갈 수 있음)
- URL이 바뀌면 폰에 설치된 기존 PWA는 옛 도메인을 그대로 가리키고, 새 도메인은 빈 데이터로 시작함
  → 지금까지 넣어둔 문장이 자동으로 안 따라옴
- 반드시 이관 전에 백업부터 뜰 것

[권장 순서]
1. 지금 폰 앱에서 설정 > 데이터 관리 > 백업 내보내기(TSV)로 백업 먼저 뜨기 (안전장치)
2. 새 이메일로 새 깃허브 계정 가입
3. 로컬 저장소를 새 깃허브 계정의 새 저장소로 push
   (git remote set-url 로 origin 주소 변경, 또는 새로 clone)
4. 새 이메일로 버셀 가입 → 새 깃허브 저장소 연결 → 배포 (URL이 기존과 달라질 수 있음을 감안)
5. 새 URL이 정상 배포됐는지 확인 후, 폰에서 새 URL로 PWA 재설치 → TSV로 데이터 복원
6. 문제없으면 기존(옛 계정) 깃허브 저장소·버셀 프로젝트는 삭제하거나 그대로 방치

[참고]
- 기존 계정 이메일만 바꾸는 방법을 쓸 경우의 주의사항(깃허브 비밀번호 설정, 보조 이메일 등록,
  2단계 인증을 OTP 앱으로 전환 등)은 이 방법을 안 쓰기로 했으므로 여기서는 생략
