
● 좋은 질문이에요. "Sonnet 5를 쓴다"는 게 실제로는 어떤 기술적 과정인지 설명드릴게요.

  지금(무료판)과 뭐가 다른가
  현재 15-2 무료판은 앱이 AI를 직접 부르지 않습니다 — 앱이 프롬프트 텍스트만 만들어주면, 사용자가 그걸 복사해서 **본인이 쓰는 AI 챗(ChatGPT 등)**에 붙여넣고, 결과를 다시 복사해서
  앱에 붙여넣는 구조예요. 그래서 앱 입장에서 AI 호출 비용이 0원이었던 거고요.
  유료판은 이 "복붙 왕복"을 없애고, 버튼 한 번 누르면 앱이 알아서 AI를 호출해서 바로 결과를 받아오는 구조로 바뀝니다. 여기서 "Sonnet 5를 쓴다"는 게 의미를 가져요.

  실제 작동 흐름

  [사용자]                [내 앱 서버(Vercel)]         [Anthropic(Claude)]
    |                            |                            |
    |-- "자동변형" 버튼 클릭 --->|                            |
    |   (원문 문장 전송)         |                            |
    |                            |-- 로그인 확인               |
    |                            |-- 이번달 사용횟수 확인(20회) |
    |                            |   (Firestore에 카운터 저장) |
    |                            |-- 넘었으면 → 거절 응답 반환  |
    |                            |-- 안 넘었으면 ↓             |
    |                            |-- API 키로 요청 전송 ------->|
    |                            |                            |-- Sonnet 5가 변형 문장 생성
    |                            |<----------- 결과 수신 -------|
    |                            |-- 사용횟수 +1               |
    |<------- 변형 결과 전달 ----|                            |
    |   (기존 15-2 미리보기      |                            |
    |    화면에 그대로 표시)      |                            |

  왜 꼭 "서버"를 거쳐야 하나 (중간 단계가 필요한 이유)

  지금 이 앱은 순수 프론트엔드(HTML/JS)라, Anthropic API 키를 앱 코드에 직접 넣으면 브라우저 개발자도구로 누구나 훔쳐볼 수 있어요. 그러면 다른 사람이 그 키로 무제한 API를 써서
  개발자 본인이 그 비용을 다 물게 됩니다. 그래서:
  - API 키는 서버(Vercel 서버리스 함수)에만 보관 — 브라우저엔 절대 안 보임
  - 앱은 서버에 "이 문장 변형해줘"라고만 요청하고, 실제 Claude 호출은 서버가 대신 함
  - 서버가 "이 사람이 로그인했는지 + 이번 달 20회 안 넘었는지"를 먼저 확인한 뒤에만 Claude를 호출 — 이게 월 20회 한도를 실제로 지키는 방법이기도 함

  비용이 왜 발생하나

  Claude API는 토큰(글자 단위) 사용량만큼 과금됩니다. 문장 하나 변형 요청할 때마다 입력+출력 토큰만큼 비용이 나가요. 그래서 "월 20회 한도"를 둔 거고, 7,000원 가격도 이 변동비를
  감안해 정해진 거예요.

  아직 안 정해진 것

  - Sonnet 5는 Claude가 "품질 대비 원가가 괜찮다"고 추천한 것뿐, 실제 개발 착수 시점에 다시 확인 필요(그때 더 저렴하거나 나은 모델이 나왔을 수도 있음)
  - Vercel 서버리스 함수 자체가 아직 코드로 존재하지 않음 — 15-2 유료판 착수 시 새로 만들어야 하는 부분

● 좋은 포인트예요. 사실 이건 이미 무료판(15-2)에서 한 번 풀어야 했던 문제라, 어떻게 풀었는지 코드를 보여드릴게요.

● 막연하게 느껴지시는 게 당연해요 — 근데 사실 이건 이미 무료판(15-2)에서 한 번 풀었던 문제라, 그 답이 이미 코드에 있습니다. 실제로 지금 쓰고 있는 프롬프트를 보여드릴게요.

  지금 무료판이 쓰는 실제 프롬프트

  ▎ "다음 한국어-영어 문장을 아래 5가지 방식으로 변형해줘. 문장 의미상 부자연스럽거나 실제로 잘 쓰지 않는 조합(예: 인사말의 의문문, 날씨 표현의 인칭 변화 등)은 억지로 만들지 말고   ▎ 자연스러운 것만 골라서 답해줘. 각 줄에 "한국어 문장" 다음 탭(Tab)을 하나 넣고 이어서 "English sentence"를 쓰는 형식으로, 결과를 코드블록 안에 한 줄에 하나씩만 적어줘(설명 없이 
  ▎ 결과만).  ▎
  ▎ 원문: {한국어} / {영어}
  ▎
  ▎ 변형 요청: 시제(현재/과거/미래/현재완료), 인칭(1인칭/2인칭/3인칭), 수(복수), 부정문, 의문문"

  이걸 보면 "그냥 변형해줘"가 아니라 3가지 원칙이 이미 들어가 있어요:

  1. 범위를 유한 목록으로 못박기 — "다양하게"가 아니라 정확히 "시제 4종·인칭 2종·수·부정문·의문문" 5가지로 한정. 이게 없으면 AI가 몇 개를 만들지, 어떤 종류로 만들지 매번 달라져서
  결과가 들쭉날쭉해짐
  2. 판단 기준 + 반례 예시 — "부자연스러운 건 만들지 마라"라고만 하면 AI도 기준이 모호한데, "인사말의 의문문, 날씨 표현의 인칭 변화" 같은 구체적 반례를 하나 붙여주면 AI가 그
  패턴으로 유추해서 훨씬 판단을 잘함
  3. 출력 형식을 강제 — "탭으로 구분", "코드블록 안에", "설명 없이" — 이게 없으면 AI가 매번 다른 형태로 답해서, 그걸 다시 파싱하는 코드(parseSentencesText)가 깨짐

  이 원칙들은 "AI가 만족스럽게 해줄까?"라는 걱정을 실제로 8월에 사용자님과 같이 다듬어서 해결한 결과물이에요(사용자 2차 확인까지 끝난 검증된 프롬프트).

  유료판(API 직접 호출)에서 추가로 할 수 있는 것

  위 3가지는 그대로 재사용하면 되고, API로 직접 호출하면 복붙 방식보다 더 확실하게 제어할 수 있는 도구들이 생깁니다:

  - 시스템 프롬프트 분리: 지금은 지시문+원문이 한 덩어리 텍스트인데, API는 "역할 지시"(예: "당신은 한영 문장 변형 전문가입니다")를 별도 채널로 줄 수 있어서 지시를 더 안정적으로
  따르게 만들 수 있음
  - 정형 출력 강제(JSON 등): 지금은 "탭으로 구분해줘"라고 말로 부탁하는 수준인데, API에서는 아예 "이 구조(JSON)로만 답해라"를 시스템 차원에서 강제하는 기능이 있어서 파싱 실패
  위험이 거의 없어짐
  - 예시 추가(few-shot): "이런 식으로 답해줘"라는 실제 예시 1~2개를 프롬프트에 끼워주면 형식 준수율이 더 올라감
  - 일관성 파라미터 조정: 창의적인 답보다 "일관되고 예측 가능한" 결과가 중요한 작업이라, 무작위성을 낮추는 설정을 쓸 수 있음
  - 실패 시 재시도 로직: 사람이 복붙할 땐 이상하면 사람이 알아서 다시 하면 되는데, 자동화되면 "결과가 이상하면 한 번 더 시도" 같은 방어 코드가 필요해짐(무료판엔 없던 새 작업거리)

  정리하면: "막연히 AI한테 던지고 잘 되길 바라는" 게 아니라, 이미 검증된 프롬프트 원칙이 있고, API로 가면 그걸 더 단단하게 만들 도구까지 있는 상황이라 실제 착수하면 생각보다 수월할
  가능성이 높아요.
